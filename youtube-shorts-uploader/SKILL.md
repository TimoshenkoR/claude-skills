# YouTube Shorts Uploader — паблишер с обязательным согласованием

Скилл умеет три вещи: **найти** видео-шортсы на диске, **показать**, какой канал авторизован,
**загрузить** выбранное видео на YouTube. Загрузка — публичное или полупубличное действие от
имени пользователя, поэтому к ней жёсткие правила.

## 🔴 Золотое правило (нарушать нельзя никогда)

**Ни одно видео не загружается на YouTube без явного согласия пользователя в этом диалоге —
на конкретный файл, конкретный канал и конкретные метаданные (заголовок, описание, теги,
приватность, «для детей»).** Без исключений, без «очевидно же», без переноса согласия с одного
видео на другое.

Это инвариант скилла. Есть тень сомнения — не загружай, спроси.

## Протокол загрузки (всегда по шагам)

1. **Проверь авторизацию.** Если `~/.yt/token.json` нет — это первый запуск, см.
   `references/setup.md` и запусти `scripts/yt_auth.py` (разовая интерактивная OAuth-авторизация
   в браузере, ничего не публикует).
2. **Определи канал.** Запусти `scripts/yt_channel.py` (read-only), покажи пользователю, какой
   канал сейчас авторизован, **если у него может быть несколько каналов** или он не упоминал канал
   явно. Не угадывай канал.
3. **Найди файл.** Если пользователь не дал точный путь — запусти
   `scripts/yt_find_shorts.py [папка]` (read-only, сканирует диск и читает метаданные через
   ffprobe, ничего не грузит). Покажи список кандидатов (путь, разрешение, длительность, размер)
   и дай пользователю выбрать. Не выбирай файл сам, если есть несколько похожих.
4. **Собери метаданные.** Заголовок, описание, теги, приватность (`public` / `unlisted` /
   `private`), «для детей» (да/нет) — спроси у пользователя или возьми из его сообщения дословно.
   **Никогда не предполагай приватность по умолчанию** — это юридически и репутационно значимое
   поле, должно быть явно указано пользователем (private/unlisted для черновика, public — только
   если пользователь прямо попросил опубликовать видимо для всех).
5. **Покажи карточку согласования.** Запусти **сухой прогон** —
   `scripts/yt_upload.py --file <path> --title "..." --privacy <...> --not-made-for-kids|--made-for-kids
   [--description "..."] [--tags "a,b,c"] [--playlist-id ...]` (без `--yes`). Он печатает карточку
   (канал + файл + все метаданные 1:1) и ничего не загружает. Покажи вывод пользователю как есть и
   спроси: «Загружаю?» Карточку формирует сам скрипт — гарантия, что превью совпадает с тем, что
   уйдёт.
6. **Дождись явного согласия.** Согласие — недвусмысленное «да / загружай / го / публикуй».
   **НЕ согласие:** молчание, «норм видео», «ок» к другому вопросу, правки без команды загрузить.
   Внёс правку в метаданные — прогони сухой прогон заново и спроси снова.
7. **Загрузи** тем же вызовом с флагом `--yes`. Флаг ставится **только после** согласия и с теми
   же файлом/метаданными, что были в карточке.
8. **Подтверди факт.** Сообщи пользователю ссылку (`youtu.be/<id>`) и канал, куда ушло видео.

Одно согласие = одна загрузка. Следующее видео — снова карточка и снова «да». Несколько файлов за
раз — покажи карточки на **все** файлы сразу и получи одно явное согласие на весь показанный
список, не загружай молча что-то сверх согласованного.

## Что можно без отдельного согласования

**Только чтение**: `yt_find_shorts.py` (поиск файлов на диске) и `yt_channel.py` (какой канал
авторизован). Ничего не публикуют и не меняют на YouTube.

## Чего скилл не делает (запрещено)

- ❌ Не загружает сам, без прямой просьбы пользователя загрузить именно это видео сейчас.
- ❌ Не выбирает приватность по умолчанию — `public` только по явной просьбе.
- ❌ Не загружает несколько файлов «заодно», если согласован был один.
- ❌ Не удаляет и не редактирует уже опубликованные на YouTube видео (скрипты этого не умеют).
- ❌ Не выдумывает заголовок/описание «за пользователя» без показа черновика на согласование.
- ❌ Не хранит и не печатает `client_secret.json` / `token.json` в чат — это секреты аккаунта.

## Технический предохранитель

`yt_upload.py` без флага `--yes` работает в режиме **сухого прогона**: резолвит канал, проверяет
файл, печатает карточку того, что *было бы* загружено, но **ничего не отправляет на YouTube**.
Реальная загрузка — только с `--yes`. Не обходи это — флаг добавляется исключительно после
согласования по протоколу выше.

## Скрипты

| Скрипт | Действие | Опасность |
|--------|----------|-----------|
| `scripts/yt_auth.py` | разовая OAuth-авторизация в браузере → `~/.yt/token.json` | запись локального токена, публикует ничего |
| `scripts/yt_channel.py` | какой канал авторизован сейчас | read-only |
| `scripts/yt_find_shorts.py [папка] [--all] [--max-seconds N]` | ищет видео-шортсы на диске → JSON (путь, разрешение, длительность, размер) | read-only |
| `scripts/yt_upload.py --file <path> --title "..." --privacy <public\|unlisted\|private> (--made-for-kids\|--not-made-for-kids) [...] [--yes]` | без `--yes` — сухой прогон; с `--yes` — реальная загрузка | ⚠️ публикация, только после согласования |

Запуск: `python3 ~/.claude/skills/youtube-shorts-uploader/scripts/<скрипт>`. Зависимости — см.
`scripts/requirements.txt` (`pip3 install -r ...`), плюс `ffmpeg`/`ffprobe` для чтения параметров
видео. Авторизация и секреты — `references/setup.md`.

## Если что-то не так

- «Нет токена / просит авторизацию» → `references/setup.md`, запусти `scripts/yt_auth.py`.
- «uploadLimitExceeded» или «quotaExceeded» → у API есть дневная квота загрузок/запросов, скажи
  пользователю, что лимит YouTube API исчерпан на сегодня, не пытайся обойти повторными попытками.
- Не уверен, тот ли канал, тот ли файл, то ли согласие → **остановись и спроси**. Лучше лишний
  вопрос, чем видео не туда или не то.
